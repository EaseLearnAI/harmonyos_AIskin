**项目概览**
- HarmonyOS（ArkTS/ArkUI）应用通常由“应用作用域”和“模块（module）”组成。你的项目中应用作用域在 `AppScope/`，主业务模块是 `entry/`。
- 构建系统使用 Hvigor；依赖管理使用 ohpm（对应 `oh-package.json5`/`oh-package-lock.json5`）。
- 前端代码主要在 `entry/src/main/ets`（ArkTS 组件与页面），资源在 `resources/`，路由与能力定义在 `module.json5`。

**顶层文件**
- `/.gitignore`
  - 控制 Git 忽略哪些文件。当前忽略了 `node_modules`、`oh_modules`、`build`、`.idea`、`.hvigor` 等产物与缓存，避免无关文件入库。
- `/build-profile.json5`
  - 应用级构建配置，定义产品 `default`、签名、SDK 版本（`6.0.0(20)`），运行环境（HarmonyOS），以及 `modules` 清单（当前仅 `entry`）。Hvigor在构建时读取它决定打哪个产品与哪些模块。
- `/code-linter.json5`
  - ArkTS 代码检查规则。限定检查 `**/*.ets`，忽略测试/构建目录；启用性能与 TypeScript 推荐规则；加入若干安全规则（禁止不安全的加密/签名算法）。
- `/hvigorfile.ts`
  - 顶层 Hvigor 入口，注册 `appTasks` 以构建应用。类似前端项目中的 `gulpfile` 或 `webpack` 入口，用来驱动整个项目的构建流水线。
- `/local.properties`
  - DevEco Studio 自动生成的本地环境配置（SDK 路径等）。不应入库；也不参与功能逻辑或前端呈现。
- `/oh-package.json5`
  - 应用级依赖清单（类似前端的 `package.json`）。当前 `devDependencies` 包含测试框架 `@ohos/hypium` 与 `@ohos/hamock`。
- `/oh-package-lock.json5`
  - 依赖锁定文件（确定版本与来源），让团队构建一致。由 ohpm 自动生成，不建议手改。

**核心目录与作用**
- `/.hvigor/`
  - Hvigor的内部数据：缓存、依赖映射、构建输出索引、报告日志等。用于加速构建与问题定位。不是业务代码。
  - `dependencyMap/` 保存各模块的依赖图；`outputs/` 下包含构建日志；`report/` 是每次构建的状态报告。
- `/.idea/`
  - IDE 工程配置（预览器设备配置、模块缓存等）。影响 DevEco 的本地行为，不影响运行产物。
- `/AppScope/`
  - 应用作用域配置与全局资源。
  - `app.json5`：应用清单（包名、版本、权限、图标、入口能力等）。
  - `resources/base/`：应用级通用资源（图标、图片、样式、字符串），可在各模块引用。
- `/doc/`
  - 文档目录，存放 ArkTS 教程、规范和资料。仅供开发参考。
- `/hvigor/`
  - Hvigor 项目配置（`hvigor-config.json5`），通常用于插件或构建行为的额外配置。
- `/oh_modules/`
  - ohpm 下载并解压的依赖包目录，类似 `node_modules`。子目录 `.ohpm/lock.json5` 是 ohpm 的内部锁；`@ohos` 下为官方库。
- `/entry/`
  - 主业务模块（module）。HarmonyOS 应用可以包含多个模块，`entry` 通常是主入口模块。
  - 主要内容：
    - `hvigorfile.ts`：模块层构建入口，配合顶层 Hvigor，定义本模块的构建任务。
    - `oh-package.json5`：模块级依赖清单。模块可以单独声明依赖（例如 UI 组件库），与应用级相互独立。
    - `build-profile.json5`：模块构建配置（若存在，则覆盖或补充顶层配置）。
    - `obfuscation-rules.txt`：混淆规则（产物发布时减少逆向风险）。
    - `build/` 与 `.preview/`：构建输出与预览配置目录（`FakeUIAbility.ets` 用于预览器模拟 UIAbility）。
    - `src/`：模块源码根
      - `main/`
        - `ets/`：ArkTS 页面与组件源码。页面通常以 `@Entry` 组件作为入口；其他 `struct`/组件文件被页面 `import` 使用。
        - `resources/`：模块资源（图片、布局、字符串等）。ArkTS 中通过 `$r('app.string.xxx')` 或 `$r('app.media.xxx')` 引用。
        - `module.json5`：模块清单，定义本模块的 `abilities`（如 `UIAbility`）、路由页面、权限、依赖关系等。前端路由与页面入口高度依赖此文件。
      - `ohosTest/` 与 `test/`：测试代码（`Hypium` 单元/集成测试、`Hamock` 模拟）；`List.test.ets`、`LocalUnit.test.ets` 是测试样例。
      - `mock/`：模拟数据配置（`mock-config.json5`），可用于开发阶段。

**如何对应到前端（ArkUI/ArkTS）**
- 前端呈现的页面与组件
  - 主要在 `entry/src/main/ets` 下的 `.ets` 文件中实现。页面文件通常包含一个 `@Entry` 装饰的组件作为页面根；内部定义状态、生命周期、UI 构建（`build()`）。
  - 非入口的 UI 组件使用 `import` 引入和组合，实现模块化复用（类似 React/Vue 组件拆分）。
- 页面路由与能力
  - `entry/src/main/module.json5` 定义 `UIAbility` 以及页面路由映射。启动页面、可导航页面都在这里声明，构建时会打包到 HAP。
- 资源与样式
  - `resources/base/`（AppScope）与 `entry/src/main/resources/`（模块级）共同提供图片、字符串、样式等。ArkTS 中通过 `$r(...)` 引用，编译期会进行资源索引与检查。
- 依赖使用
  - UI/工具库通过 `ohpm` 安装后位于 `oh_modules/`，在 `.ets` 中 `import` 使用。版本与来源由 `oh-package.json5` 和 `oh-package-lock.json5` 控制。

**模块化关系说明**
- 应用（AppScope）与模块（entry）
  - `AppScope` 提供应用范围的元信息和通用资源；`entry` 专注业务实现与模块级配置。
  - 多模块场景下，每个模块都有自己的 `module.json5` 与 `oh-package.json5`，互相独立但共享应用级资源。
- 组件与页面
  - 页面是由组件组合而成的 ArkTS 结构。组件之间通过 `import` 解耦，形成清晰的层次（页面 → 业务组件 → 基础组件）。
  - 建议按功能域划分子目录（例如 `ets/pages/`、`ets/components/`、`ets/services/`），提高可维护性。
- 测试与业务
  - `ohosTest` 与 `test` 模块化隔离业务代码，使用 `Hypium`、`Hamock` 进行单元和集成测试，不影响生产构建。

**构建与运行流程（简述）**
- 构建入口：顶层 `hvigorfile.ts` 调用内置 `appTasks`，根据 `build-profile.json5` 的 `products` 和 `modules` 编排构建。
- 模块打包：读取 `entry/src/main/module.json5` 生成能力与路由配置，编译 `ets` 与资源，输出到 `build/`，最终产出 HAP 包。
- 依赖解析：ohpm 根据 `oh-package-lock.json5` 下载并链接依赖到 `oh_modules/`。
- 预览与模拟：`.preview/fakeuiability/FakeUIAbility.ets` 用于预览器快速查看页面效果，不影响正式产物。

**快速定位前端代码的路径**
- 页面与组件源码位置：`/entry/src/main/ets/`
- 路由与能力配置：`/entry/src/main/module.json5`
- 模块资源：`/entry/src/main/resources/`
- 应用清单与全局资源：`/AppScope/app.json5` 与 `/AppScope/resources/base/`

- 添加统一样式或图片：放到 `resources` 对应目录，使用 `$r` 引用。
